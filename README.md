# 博物馆藏品管理系统 · 在线演示

> 数据库课程设计 — 博物馆藏品管理系统前端（演示模式，内置 Mock 数据，无需后端）。

**在线访问：** https://zhj0325.github.io/museum-collection-demo/

## 演示账号（密码均为 `123456`）

| 角色 | 账号 | 主要职责 |
|------|------|----------|
| 管理员 | `admin` | 审批出/入库与修复申请、指派专家鉴定/修复、审核鉴定结论、藏品增删改查 |
| 库房管理员 | `keeper1` | 出入库登记、存放记录查询、藏品浏览 |
| 展览负责人 | `manager1` | 设计常设/临时展览、安排展品、提交出/入库与修复申请 |
| 文物专家 | `expert1` | 浏览藏品、提交鉴定结论、执行修复并登记 |

登录页提供四个「快速进入」按钮，可一键体验各角色工作台。
右下角「演示模式」角标可查看**操作日志**（每一次登录、新增、审批、登记都被记录并保留），
也可一键重置演示数据。

## 系统需求概述

1. **藏品管理** — 藏品（编号、名称、类型、图片、级别）的浏览与增删改
2. **常设展览安排** — 展览负责人设计展览、安排展品、提交出库申请，管理员审批
3. **临时/巡展安排** — 临展设计与展品安排；展毕提交入库申请，管理员审批
4. **库房管理** — 审批通过后，库房管理员进行出入库登记（库房含温湿度信息）
5. **鉴定登记** — 管理员指派文物专家鉴定，专家提交结论并认定级别，管理员审核
6. **修复申请及登记** — 申请修复 → 审批 → 委托专家修复（记录原始/修复后状态）→ 修复后入库

## 技术栈

- **前端**：React 19 + Vite + React Router（HashRouter），手写设计系统（文博风格：深棕 + 鎏金）
- **后端**（完整版，本演示以浏览器内 Mock 替代）：Spring Boot + MyBatis-Plus + JWT
- **数据库**（完整版）：MySQL，15 张表满足 3NF；各角色工作台复合索引、
  FULLTEXT ngram 中文全文索引、乐观锁版本控制、CHECK 域约束

## 演示模式说明

- 触发条件（满足其一）：域名为 `*.github.io` / URL 带 `?demo` / 构建时 `VITE_DEMO=1`
- 所有接口由浏览器内 Mock 层接管，数据与操作日志保存在 `localStorage`（按浏览器持久保留）
- 可完整体验「出库申请 → 管理员审批 → 库房出库登记」等全部业务闭环

## 本地开发（连接真实后端）

```bash
npm install
npm run dev   # 代理 /api 至 localhost:8080（Spring Boot）
```
